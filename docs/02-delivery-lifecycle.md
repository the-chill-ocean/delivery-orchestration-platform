# Жизненный цикл доставки

## 1. Основные статусы доставки

| Статус | Описание |
|---|---|
| `CREATED` | Доставка создана во внутренней системе, начинается оформление у перевозчика |
| `ACCEPTED` | Перевозчик подтвердил создание доставки и принял её к исполнению |
| `PICKED_UP` | Отправление передано перевозчику |
| `IN_TRANSIT` | Отправление находится в процессе транспортировки |
| `OUT_FOR_DELIVERY` | Отправление передано курьеру для доставки получателю |
| `READY_FOR_PICKUP` | Отправление доставлено в выбранный ПВЗ и доступно для получения |
| `DELIVERED` | Отправление успешно передано получателю |

## 2. Альтернативные состояния

| Статус | Описание |
|---|---|
| `CANCELLED` | Доставка отменена до успешного завершения |
| `RETURN_IN_PROGRESS` | Начат возврат отправления |
| `RETURNED` | Отправление возвращено отправителю |
| `DELIVERY_FAILED` | Доставка не может быть завершена без дополнительного действия |

## 3. Варианты успешного завершения

### Курьерская доставка

`CREATED → ACCEPTED → PICKED_UP → IN_TRANSIT → OUT_FOR_DELIVERY → DELIVERED`

### Доставка в ПВЗ

`CREATED → ACCEPTED → PICKED_UP → IN_TRANSIT → READY_FOR_PICKUP → DELIVERED`

## 4. Нормализация статусов перевозчиков

Внешние службы доставки могут использовать более детальные собственные статусы.

Например, статусы:

- «Принято в сортировочном центре»;
- «Покинуло сортировочный центр»;
- «Прибыло в транзитный город»;

могут быть нормализованы платформой во внутренний статус `IN_TRANSIT`.

При этом исходный статус перевозчика может сохраняться отдельно для диагностики и отображения детальной информации о доставке.
## 5. Возврат после истечения срока хранения

Если пользователь не забрал отправление из ПВЗ до окончания срока хранения, доставка переходит в процесс возврата:

`READY_FOR_PICKUP → RETURN_IN_PROGRESS → RETURNED`

Событие истечения срока хранения инициирует переход в `RETURN_IN_PROGRESS`.

Статус `RETURNED` является терминальным.
## 6. Неудачная попытка курьерской доставки

Если курьер не смог передать отправление получателю, доставка не считается завершённой.

Доставка переходит в статус `DELIVERY_FAILED`, который в данном случае означает неудачную попытку доставки и не является терминальным.

В зависимости от возможностей перевозчика и выбора пользователя возможны следующие сценарии:

- повторная курьерская доставка:

  `DELIVERY_FAILED → OUT_FOR_DELIVERY → DELIVERED`

- перенаправление отправления в доступный ПВЗ:

  `DELIVERY_FAILED → IN_TRANSIT → READY_FOR_PICKUP → DELIVERED`

- возврат отправителю, если дальнейшая доставка невозможна:

  `DELIVERY_FAILED → RETURN_IN_PROGRESS → RETURNED`

При неудачной попытке доставки пользователь должен быть уведомлён и, если это предусмотрено правилами доставки, получить возможность выбрать дальнейший способ получения отправления.
## 7. Разрешённые переходы между статусами

| Текущий статус | Событие / условие | Следующий статус | Комментарий |
|---|---|---|---|
| `CREATED` | Перевозчик подтвердил создание доставки | `ACCEPTED` | Доставка зарегистрирована у перевозчика |
| `CREATED` | Создание доставки отменено | `CANCELLED` | Доставка не была передана перевозчику |
| `ACCEPTED` | Перевозчик получил отправление | `PICKED_UP` | Отправление физически передано перевозчику |
| `ACCEPTED` | Доставка отменена до передачи отправления | `CANCELLED` | Возможность отмены зависит от правил перевозчика |
| `PICKED_UP` | Началась транспортировка | `IN_TRANSIT` | Отправление движется по логистической сети перевозчика |
| `PICKED_UP` | Инициирован возврат после передачи отправления перевозчику | `RETURN_IN_PROGRESS` | Возврат допускается правилами Carrier |
| `IN_TRANSIT` | Отправление передано курьеру | `OUT_FOR_DELIVERY` | Используется для курьерской доставки |
| `IN_TRANSIT` | Отправление поступило в выбранный ПВЗ | `READY_FOR_PICKUP` | Используется для доставки в ПВЗ |
| `IN_TRANSIT` | Инициирован возврат во время транспортировки | `RETURN_IN_PROGRESS` | Возможность возврата согласована с Carrier |
| `OUT_FOR_DELIVERY` | Отправление передано получателю | `DELIVERED` | Успешное завершение доставки |
| `OUT_FOR_DELIVERY` | Курьер не смог передать отправление | `DELIVERY_FAILED` | Неудачная попытка доставки |
| `DELIVERY_FAILED` | Назначена повторная курьерская доставка | `OUT_FOR_DELIVERY` | Выполняется новая попытка доставки |
| `DELIVERY_FAILED` | Пользователь выбрал получение через ПВЗ | `IN_TRANSIT` | Отправление перенаправляется в ПВЗ |
| `DELIVERY_FAILED` | Продолжение доставки невозможно | `RETURN_IN_PROGRESS` | Начинается возврат отправителю |
| `READY_FOR_PICKUP` | Пользователь получил отправление | `DELIVERED` | Успешное завершение доставки |
| `READY_FOR_PICKUP` | Истёк срок хранения в ПВЗ | `RETURN_IN_PROGRESS` | Отправление не было получено пользователем |
| `READY_FOR_PICKUP` | Пользователь запросил возврат из ПВЗ | `RETURN_IN_PROGRESS` | Возврат допускается правилами Carrier |
| `RETURN_IN_PROGRESS` | Отправление возвращено отправителю | `RETURNED` | Возврат завершён |

## 8. Терминальные статусы

Терминальными считаются статусы, после которых жизненный цикл доставки завершён:

- `DELIVERED` — отправление успешно получено;
- `CANCELLED` — доставка отменена;
- `RETURNED` — отправление возвращено отправителю.

Статус `DELIVERY_FAILED` не является терминальным, так как после неудачной попытки доставки возможны:

- повторная курьерская доставка;
- перенаправление в ПВЗ;
- возврат отправителю.

## 9. Основные успешные сценарии

### Курьерская доставка

`CREATED → ACCEPTED → PICKED_UP → IN_TRANSIT → OUT_FOR_DELIVERY → DELIVERED`

### Доставка в ПВЗ

`CREATED → ACCEPTED → PICKED_UP → IN_TRANSIT → READY_FOR_PICKUP → DELIVERED`

## 10. Альтернативные сценарии

### Неудачная курьерская доставка с повторной попыткой

`OUT_FOR_DELIVERY → DELIVERY_FAILED → OUT_FOR_DELIVERY → DELIVERED`

### Неудачная курьерская доставка с перенаправлением в ПВЗ

`OUT_FOR_DELIVERY → DELIVERY_FAILED → IN_TRANSIT → READY_FOR_PICKUP → DELIVERED`

### Возврат после неудачной доставки

`OUT_FOR_DELIVERY → DELIVERY_FAILED → RETURN_IN_PROGRESS → RETURNED`

### Возврат после истечения срока хранения

`READY_FOR_PICKUP → RETURN_IN_PROGRESS → RETURNED`
## 11. Правила отмены доставки

Пользователь может инициировать отмену заказа, однако результат отмены доставки зависит от её текущего состояния.

До физической передачи отправления перевозчику доставка может быть отменена:

`CREATED → CANCELLED`

`ACCEPTED → CANCELLED`

После перехода доставки в статус `PICKED_UP` отправление уже находится у перевозчика. В этом случае доставка не переводится в `CANCELLED`.

Если заказ отменяется после передачи отправления перевозчику, должен быть инициирован процесс возврата:

`PICKED_UP → RETURN_IN_PROGRESS → RETURNED`

`IN_TRANSIT → RETURN_IN_PROGRESS → RETURNED`

Для более поздних этапов возможность возврата зависит от текущего состояния доставки и правил конкретного перевозчика.

Статус `CANCELLED` используется только в случаях, когда фактическая доставка ещё не началась.

## 12. Конкурентное изменение статуса при отмене

Состояние доставки может измениться между отображением данных пользователю и обработкой команды на отмену.

Например:

`ACCEPTED → PICKED_UP`

может произойти одновременно с попыткой пользователя отменить доставку.

При обработке запроса на отмену платформа должна повторно проверить актуальный статус доставки.

Переход в `CANCELLED` разрешён только из состояний:

- `CREATED`;
- `ACCEPTED`.

Если к моменту обработки запроса доставка уже перешла в `PICKED_UP` или более поздний статус, отмена должна быть отклонена.

Пользователю возвращается информация о том, что состояние доставки изменилось, после чего интерфейс должен отобразить актуальный статус и недоступность операции отмены.
