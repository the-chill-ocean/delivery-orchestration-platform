## 8. Основные бизнес-сущности

### Delivery

Представляет процесс доставки, которым управляет платформа.

Delivery связывает заказ с выбранным способом доставки и хранит текущее состояние жизненного цикла доставки.

Владельцем сущности является Delivery Orchestration Platform.

### DeliveryOffer

Представляет рассчитанный вариант доставки, который может быть предложен пользователю во время оформления заказа.

Предложение может содержать способ доставки, стоимость, ожидаемый срок, перевозчика или ПВЗ и период актуальности.

DeliveryOffer существует до создания фактической доставки и может стать неактуальным до оплаты заказа.

### Carrier

Представляет внешнюю службу доставки, интегрированную с платформой.

Например:

- СДЭК;
- DPD;
- другие подключённые перевозчики.

Carrier содержит информацию, необходимую платформе для определения возможностей и ограничений конкретного перевозчика.

### PickupPoint

Представляет конкретный пункт выдачи заказов, принадлежащий определённому перевозчику.

Пользователь может выбрать PickupPoint при использовании способа доставки в ПВЗ.

### Shipment

Представляет физическое отправление, которое должно быть передано перевозчику и доставлено получателю.

Shipment содержит параметры, необходимые для расчёта и выполнения доставки: вес, габариты, тип содержимого и объявленную ценность.

### Order

Order является внешней сущностью.

Владельцем заказа является Order Service. Delivery Orchestration Platform использует идентификатор заказа для связи доставки с заказом, но не управляет жизненным циклом Order.
### 8.1. Связь заказа, доставки и отправления

Один заказ может быть разделён на несколько физических отправлений.

Причинами разделения могут быть:

- товары находятся на разных складах;
- для разных товаров используются разные перевозчики;
- товары имеют разные ограничения по доставке;
- части заказа имеют разные ожидаемые даты доставки.

Поэтому связь между Order и Delivery является отношением один-ко-многим:

`Order 1 → N Delivery`

Каждая Delivery описывает отдельный процесс доставки конкретного Shipment.

Это позволяет независимо управлять статусом, перевозчиком, сроком и способом доставки каждой части заказа.

Пример:

`Order #100`

- `Delivery #1` — товар со склада A, статус `DELIVERED`;
- `Delivery #2` — товар со склада B, статус `IN_TRANSIT`.

Order остаётся внешней сущностью и управляется Order Service.
### 8.3. DeliveryOffer

DeliveryOffer представляет рассчитанный вариант доставки для конкретного Shipment.

Основные данные:

- `offerId` — идентификатор предложения;
- `shipmentId` — идентификатор отправления;
- `deliveryType` — способ доставки (`COURIER`, `PICKUP_POINT`);
- `carrierId` — перевозчик, рассчитавший вариант доставки;
- `pickupPointId` — ПВЗ для доставки в пункт выдачи;
- `price` — стоимость доставки;
- `currency` — валюта;
- `estimatedDeliveryDate` / `estimatedDeliveryPeriod` — ожидаемый срок доставки;
- `validUntil` — срок актуальности предложения.

Одно Shipment может иметь несколько DeliveryOffer.

После истечения `validUntil` предложение должно быть повторно проверено или рассчитано заново.

### 8.4. Delivery

Delivery представляет фактический процесс доставки конкретного Shipment.

Основные данные:

- `deliveryId` — внутренний идентификатор доставки;
- `orderId` — идентификатор заказа во внешней системе заказов;
- `shipmentId` — идентификатор физического отправления;
- `deliveryOfferId` — предложение доставки, на основании которого была создана Delivery;
- `deliveryType` — способ доставки (`COURIER`, `PICKUP_POINT`);
- `pickupPointId` — выбранный ПВЗ, если используется доставка в пункт выдачи;
- `status` — текущий нормализованный статус доставки;
- `price` — зафиксированная стоимость доставки;
- `estimatedDeliveryFrom` — минимальная согласованная дата доставки;
- `estimatedDeliveryTo` — максимальная согласованная дата доставки;
- `createdAt` — дата создания;
- `updatedAt` — дата последнего изменения.

Delivery хранит состояние фактической доставки после выбора и подтверждения DeliveryOffer.
### 8.5. Shipment

Shipment представляет физическое отправление, для которого платформа рассчитывает и организует доставку.

Основные данные:

- `shipmentId` — идентификатор отправления;
- `orderId` — идентификатор заказа, частью которого является отправление;
- `originLocationId` / `warehouseId` — точка отправления;
- `weight` — вес отправления;
- `dimensions` — габариты отправления;
- `contentType` — тип содержимого;
- `declaredValue` — объявленная ценность;
- `items` — состав отправления или ссылки на позиции заказа, если эта информация необходима для проверки ограничений доставки.

Один Order может содержать несколько Shipment.

Для каждого Shipment варианты доставки рассчитываются независимо, поскольку разные отправления могут иметь разные точки отправления, параметры, ограничения, перевозчиков и сроки доставки.

### Владение и snapshot Shipment

Delivery Orchestration Platform не является источником истины для жизненного цикла Shipment.

При расчёте `DeliveryOffer` платформа сохраняет локальный snapshot параметров Shipment, необходимых для последующей работы с Carrier:

- `shipmentId`;
- `originLocationId`;
- адрес назначения;
- вес;
- габариты;
- тип содержимого;
- объявленную ценность.

Snapshot используется при последующем создании `Delivery` и `DeliveryAttempt`.

Если параметры Shipment, влияющие на доставку, изменились, ранее рассчитанный `DeliveryOffer` должен считаться неактуальным и требуется повторный расчёт.
### 8.6. Carrier

Carrier представляет внешнюю службу доставки, подключённую к платформе.

Основные данные:

- `carrierId` — внутренний идентификатор перевозчика;
- `name` — наименование перевозчика;
- `status` — доступность перевозчика для новых доставок;
- `supportedDeliveryTypes` — поддерживаемые способы доставки;
- `supportedRegions` — обслуживаемые регионы;
- `maxWeight` — ограничение по весу;
- `maxDimensions` — ограничения по габаритам;
- `supportedContentTypes` — допустимые типы содержимого;
- `maxDeclaredValue` — максимально допустимая объявленная ценность.

Идентификатор доставки во внешней системе перевозчика (`carrierDeliveryId`) хранится в `DeliveryAttempt`.

Это необходимо, поскольку одна `Delivery` может иметь несколько попыток выполнения через разных Carrier, и каждая попытка может иметь собственный внешний идентификатор.
### 8.7. PickupPoint

PickupPoint представляет конкретный пункт выдачи заказов, принадлежащий определённому перевозчику.

Основные данные:

- `pickupPointId` — внутренний идентификатор ПВЗ;
- `carrierId` — идентификатор перевозчика;
- `externalPickupPointId` — идентификатор ПВЗ во внешней системе перевозчика;
- `address` — адрес пункта выдачи;
- `latitude` / `longitude` — географические координаты;
- `status` — доступность ПВЗ для новых доставок;
- `workingHours` — график работы;
- `maxWeight` — ограничение по весу, если применяется;
- `maxDimensions` — ограничения по габаритам, если применяются.

Стоимость и ожидаемый срок доставки до конкретного ПВЗ относятся к DeliveryOffer, а не к PickupPoint.

### 8.8. Связи между сущностями

| Сущность A | Связь | Сущность B | Обоснование |
|---|---|---|---|
| `Order` | 1:N | `Shipment` | Один заказ может быть разделён на несколько физических отправлений |
| `Shipment` | 1:N | `DeliveryOffer` | Для одного отправления может быть рассчитано несколько вариантов доставки |
| `Shipment` | 1:0..1 | `Delivery` | До выбора варианта фактической доставки может не существовать; после создания Shipment связан с одной Delivery |
| `Carrier` | 1:N | `DeliveryOffer` | Один перевозчик может предоставить множество предложений для разных отправлений |
| `Carrier` | 1:N | `PickupPoint` | Один перевозчик может иметь множество пунктов выдачи |
| `Delivery` | 1:N | `DeliveryAttempt` | Одна доставка может иметь несколько попыток выполнения |
| `Carrier` | 1:N | `DeliveryAttempt` | Один перевозчик может выполнять множество попыток доставки |
Дополнительно:

`DeliveryOffer N:1 Carrier`

`PickupPoint N:1 Carrier`


### 8.9. DeliveryAttempt

DeliveryAttempt представляет отдельную попытку создать или выполнить Delivery через конкретного перевозчика.

Одна Delivery может иметь несколько DeliveryAttempt, если первоначальный перевозчик оказался недоступен или не смог выполнить доставку.

Основные данные:

- `deliveryAttemptId` — идентификатор попытки;
- `deliveryId` — идентификатор Delivery;
- `carrierId` — перевозчик, через которого выполняется попытка;
- `carrierDeliveryId` — идентификатор доставки во внешней системе перевозчика;
- `status` — состояние попытки;
- `failureReason` — причина неуспешной попытки;
- `createdAt` — время создания попытки;
- `updatedAt` — время последнего изменения.

Связь:

`Delivery 1:N DeliveryAttempt`

Для одной Delivery может существовать несколько попыток работы с разными перевозчиками.

Пример:

`Delivery #900`

- `DeliveryAttempt #1` — СДЭК, `FAILED`;
- `DeliveryAttempt #2` — DPD, `ACCEPTED`.

### 8.10. Статусы DeliveryAttempt

| Статус | Описание |
|---|---|
| `PENDING` | Попытка создана, ожидается результат взаимодействия с перевозчиком |
| `ACCEPTED` | Перевозчик подтвердил создание доставки |
| `FAILED` | Создать доставку через данного перевозчика не удалось |
| `CANCELLED` | Попытка отменена до завершения |

Для неуспешных попыток дополнительно сохраняется `failureReason`.

Пример:

`PENDING → FAILED`

`failureReason = CARRIER_UNAVAILABLE`
### 8.11. Повторный выбор перевозчика

Если DeliveryAttempt завершается со статусом `FAILED`, платформа может создать новую попытку доставки через другого подходящего перевозчика.

Автоматическое переключение Carrier допускается для курьерской доставки (`COURIER`), если:

- способ доставки не изменяется;
- стоимость для пользователя не увеличивается;
- ожидаемый срок остаётся в согласованных пределах;
- новый Carrier поддерживает ограничения Shipment.

Пример:

`DeliveryAttempt #1: CDEK → FAILED`

`DeliveryAttempt #2: DPD → PENDING → ACCEPTED`

Для доставки в ПВЗ (`PICKUP_POINT`) автоматическая смена Carrier не допускается, поскольку выбранный пользователем PickupPoint принадлежит конкретному перевозчику.

Если Carrier не может выполнить доставку в выбранный ПВЗ, пользователю необходимо предложить альтернативные варианты и получить его подтверждение.

Если при курьерской доставке альтернативный перевозчик требует изменения стоимости, срока или других согласованных условий, автоматическое переключение также не выполняется.

В таких случаях платформа должна инициировать согласование новых условий с пользователем. Новая попытка доставки создаётся после получения необходимого подтверждения.
